# Status

Follow `progress.md`; `status` remains a compatibility alias. Run `overview`. This is read-only and works before initialization. Summarize
setup phase, counts, review queue, unfinished runs/tasks, and the next useful
step. Read saved records if more context is needed. Do not mutate content
statuses: the terminal `status <id> <state>` command is a separate write action.
An unfinished kickoff resumes through `start`; a weekly run resumes through `week`.
